## Design Specificity Verdict

**Arquitectura de interacción propia del producto; gramática visual todavía próxima a una plantilla
de consola técnica.**

Task Detail expresa con claridad una estructura que no podría trasladarse sin cambios a un gestor
genérico: Task, Cycle, Run, Delivery, Questions, Spec, verificación, provenance y versión
optimista. La identidad visual también tiene señales propias —Oxanium, geometría recta, superficies
frías, azul de señal y metadata literal—, pero Projects, Automation y Notifications repiten
composiciones de cards que podrían pertenecer a otro backoffice.

La evaluación determinista terminó limpia: `detect.mjs` devolvió exit 0 y cero findings sobre
`apps/web/src`. No hubo falsos positivos. No existía una superficie nativa para mostrar un overlay
fiable; como evidencia visual acotada se ejecutó el caso Playwright de marca/shell en Desktop Chrome
y Pixel 7, con dos resultados correctos.

## Overall Impression

AIWS ya comunica mejor la complejidad del dominio que la mayoría de consolas operativas. La mayor
oportunidad no es hacerla más vistosa, sino cerrar la distancia entre lo que una persona ve, lo que
el documento semántico comunica y el artefacto exacto que una mutación de alto impacto aprobará.

## What's Working

1. **Task Detail hace visible el modelo real.** El resumen vigente, timeline por Cycle, Run activo,
   inspector y Delivery convierten un agregado complejo en una consola comprensible.
2. **La recuperación es de primera clase.** Offline conserva snapshot, los conflictos conservan
   borradores, los uploads informan por fichero y la sesión mantiene la URL de retorno.
3. **Móvil conserva información y autoridad.** Tablas se convierten en cards equivalentes y el
   inspector completo vive en un Sheet con foco gestionado.

## Priority Issues

### P1 — Ready puede aprobar una Spec persistida distinta del borrador visible

- **What:** `SpecSection` mantiene `spec` y `dirty` localmente, mientras `TaskHeader` decide Ready
  mediante `canReady(task)` sobre `task.curatorSpec` persistida.
- **Why it matters:** la decisión más importante puede aplicarse a un artefacto distinto del que la
  persona cree estar revisando.
- **Fix:** elevar el dirty state de Spec al coordinador de Task Detail, bloquear Ready mientras haya
  draft y ofrecer “Guardar Spec y continuar” o enfocar el inspector.
- **Suggested command:** `$impeccable harden Task Detail Ready and Curator Spec`.

### P1 — Project Detail acumula commit boundaries y prerrequisitos silenciosos

- **What:** repositorio, archivo, automatización, Verification Contract, readiness y Tasks conviven
  en una página larga; “Guardar configuración” puede quedar disabled sin explicar el perfil o rama
  ausente.
- **Why it matters:** la persona debe recordar qué región está dirty y deducir por qué no puede
  guardar.
- **Fix:** checklist local de readiness junto al CTA, identificación de la sección dirty y
  navegación/progressive disclosure entre regiones.
- **Suggested command:** `$impeccable distill Project Detail configuration`.

### P1 — La jerarquía visual no coincide con la semántica del documento

- **What:** `CardTitle` y `EmptyTitle` renderizan `div`; Login y 404 carecen de heading real;
  Project Detail puede producir dos `h1`; el Select de account scope al importar no tiene label o
  nombre accesible.
- **Why it matters:** la navegación por headings no reproduce la estructura que ve una persona y
  una decisión crítica de importación queda ambigua.
- **Fix:** un `h1` por página, `h2` por región y `h3` en cards mediante una API semántica explícita;
  añadir label “Ámbito de cuenta”.
- **Suggested command:** `$impeccable harden semantic hierarchy and managed import form`.

### P1 — Crear un Project gestionado permanece oculto en la arquitectura de información

- **What:** Projects solo presenta “Crear Project” local; la importación gestionada aparece dentro
  de Automation.
- **Why it matters:** una persona nueva no puede reconocer las dos vías válidas sin conocer antes
  el modelo interno.
- **Fix:** enlazar desde Projects/Create Project a “Importar repositorio gestionado”, conservando
  los endpoints y rutas actuales.
- **Suggested command:** `$impeccable clarify Project onboarding paths`.

### P2 — Parte del copy expone representaciones backend

- **What:** estados de Connection, `authMode`, tipos de Question y estados de
  Delivery/verificación se muestran como valores técnicos o transformaciones mecánicas.
- **Why it matters:** obliga a traducir códigos justo durante diagnóstico y recuperación.
- **Fix:** presentation maps centralizados con label y consecuencia accionable, conservando los
  nombres oficiales del dominio.
- **Suggested command:** `$impeccable clarify operational states`.

## Persona Red Flags

### Alex — Power User

- Los filtros compartibles, tablas, links directos y copia de IDs son eficientes.
- Project Detail exige varias operaciones de guardado sin señalar claramente qué bloque está dirty.
- No hay aceleradores locales para abrir inspector, guardar el editor activo o saltar a la siguiente
  Question; no se propone añadir shortcuts globales fuera del MVP.

### Jordan — First-Timer

- “Crear Project” parece la única entrada; la vía gestionada no se descubre desde Projects.
- Verification Contract, probe profundo, credential reference, Ready policy, Cycle y Delivery se
  acumulan sin una explicación centrada en la tarea.
- Un CTA disabled no siempre explica el perfil o rama que falta.

### Casey — Mobile Operator

- El Sheet del inspector conserva capacidad y foco.
- Ready permanece arriba mientras Curator Spec vive tras “Abrir inspector”, separando decisión y
  evidencia.
- Project Detail es una página muy larga sin navegación interna; controles frecuentes de 32–36 px
  son menos cómodos que un target táctil de 44 px.

## Minor Observations

- El gradiente radial de Login contradice el guardrail documentado de no usar gradientes.
- Attention hace polling cada 15 segundos sin mostrar freshness y no tiene visita directa en la
  matriz E2E.
- La suite tampoco visita directamente `/projects/new`, `/` ni la ruta 404.
- El build advierte de al menos un chunk Web superior a 500 kB minificado.
- Notifications destaca positivamente por explicar privacidad, estado dirty y que la prueba usa la
  configuración persistida.

## Questions to Consider

- ¿Ready aprueba la Spec guardada o la Spec que la persona tiene delante?
- ¿Project Detail es un registro permanente, un flujo de setup o ambos?
- ¿Puede “Crear Project” empezar con una elección explícita entre local y gestionado sin cambiar el
  contrato?
- ¿Qué estados técnicos necesitan conservar su valor literal y cuáles deben responder “qué pasó y
  qué hago ahora”?
